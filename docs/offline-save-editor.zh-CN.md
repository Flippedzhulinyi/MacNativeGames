# TOTK 离线存档修改器（Mac）

在仓库根目录双击 **Open TOTK Save Editor.command** 启动。窗口需要 Tk 8.6 或更新版本；启动器会优先选择兼容的 Homebrew Python，并跳过 macOS 自带的旧版 Tk。也可以从终端启动：

```sh
TOTK_SAVE_EDITOR_PYTHON=/opt/homebrew/bin/python3.14 \
  "./Open TOTK Save Editor.command"
```

若提示没有兼容的 Tk，可安装 `brew install python-tk@3.14`，然后双击启动器；或按上面的命令显式指定 Python。

## 使用

1. 完全退出 TOTK。窗口顶部显示“离线就绪”时才可编辑；游戏运行期间会拒绝写入。
2. 默认扫描 `~/Library/Application Support/MacNativeGames/TOTK/profile`，也可选择另一个包含 `save/` 目录的 profile。
3. 存档下拉框使用游戏 `caption.sav` 中记录的位置，并显示到秒的 `progress.sav` 保存时间；按文件修改时间排序的第一项标记为“最新保存”。检查点位置会显示检查点编号，避免被误标为未知。
4. 修改已有物品、卢比或装备：选择“素材”“箭”“卢比”“武器”“盾牌”或“弓”，再选择所选存档中已有的条目。箭和素材数量范围为 0–999，卢比范围为 0–999,999；装备可设置当前耐久，不超过装备的游戏上限。
5. 添加新装备：点“添加新装备…”，选择武器、盾牌或弓，再从中文目录选择具体装备。新增装备以基础耐久加入，不带强化词条或融合物；只使用对应类型的空槽，不会覆盖已有装备。没有可验证空槽时会取消操作。
6. 激活地底灯根：选择存档后点“激活全部灯根…”，确认当前激活数量及进度影响后操作。此功能只写入 120 个灯根的激活状态，不主动修改地面神庙；地图显示、传送、照明及相关进度仍需在游戏内验证。
7. 确认后，工具先复制并校验整个存档槽，再原子写入 `progress.sav`。完成后修改会直接成为该 profile 的活动存档，启动游戏读取所选槽即可。

备份保存在 `~/Library/Application Support/MacNativeGames/TOTK/save-editor-backups/`，按 profile 和槽位区分。每次修改会先创建并验证新备份，写入成功并复核后，自动删除**同一 profile、同一槽位**更早的备份，只保留最新一份；其他槽位的备份不受影响。若修改或复核失败，不会清理之前的备份。工具保留 `progress.sav` 其余字节不变，并在写入后复核修改值和数据结构。若存档结构不匹配、在窗口打开后发生变化、备份失败或游戏持有运行锁，工具会拒绝修改。

## 范围和注意事项

- 这是离线存档编辑器，不附加到游戏进程、不读取或写入运行中游戏的内存，也不需要重新编译游戏。
- 列表显示存档中现有的普通箭、素材、卢比，以及武器、盾牌和弓的装备槽；不包含临时挑战背包。箭和素材的堆叠上限为 999，卢比上限为 999,999。装备耐久上限按 TOTK 1.4.3 游戏数据中的 `MaxLife` 计算，并应用已识别的耐久强化词条；没有可靠上限数据的已有装备会显示为不可编辑，不会猜测数值。
- 武器、盾牌和弓只会修改所选槽位的当前耐久，不改变攻击力、装备属性或融合材料。耐久值可设置为 0 至该装备的上限。
- 激活灯根会改变地底探索进度，可能影响传送和完成度；不会主动修改神庙状态或灯根“已发现”字段。工具要求 120 个灯根字段均存在、类型和状态均可识别，否则拒绝修改。字段名单参考 [TOTK 存档编辑器](https://github.com/marcrobledo/savegame-editors/blob/b4db8cd11157c6d5ae54a0a5edc88dba82aebe9d/zelda-totk/zelda-totk.completism.js)；游戏内是否完全点亮地图仍需验证。
- 新增装备只能从随工具提供的已验证 ID/名称/耐久目录选择，并且只能加入空装备槽。工具会将新装备初始化为基础 `MaxLife`、无效果词条（`None`）和无融合值；如果存档空槽的初始字段与已验证格式不同，则拒绝添加。
- 存档位置名称从游戏保存的 caption 元数据读取；若无法识别，显示“未知保存位置”。时间来自存档文件的本机修改时间。
- 神庙位置会显示游戏内简体中文名称，而不是 `Dungeon068` 一类内部编号；名称映射依据 [TOTK shrine ID/name 数据](https://github.com/tingod/totk/blob/90a08cdd1b207e9e636ff6c36b14c474ad88671c/data/category/totk_shrines.csv) 的简体中文列。
- 素材名称优先从玩家自己的游戏简体中文资源读取，包含游戏 `PouchContent` 中可识别的名称，不需要联网，也无需修改游戏文件。读取需要带 `compression.zstd` 的 Python 3.14 或更新版本；启动器默认优先使用 Python 3.14。默认优先尝试 `~/Documents/Games/TOTK_build/totk/extracted/v143/romfs`，否则仅在同一目录下只有一个版本时自动选择；若未找到或有多个目录，点击“选择游戏名称数据…”选择包含 `index.json` 和 `romfs.bin` 的 `romfs` 目录，工具会记住该目录。窗口显示加载数量或错误；未加载时使用内置的少量名称表，仍无法识别的物品显示“未收录名称”和内部 ID，不会猜测名称。
- 装备名称同样按内部 ID 显示简体中文，名称表参照上述物品名称数据；基础耐久上限来自 TOTK 1.4.3 的 `GameActorInfo` 游戏数据。
- 每个存档槽只保留最新备份；如果旧备份因权限等原因无法删除，界面会明确提示，不会影响已验证完成的修改。
- 首个验证范围为 TOTK `progress.sav` 的已知 1.4.3 布局。即使版本标记不同，也只有在对应背包/装备字段及数组结构通过严格校验时才会显示可编辑条目；不认识的布局不会尝试写入。
- 修改后建议先在游戏中确认该槽可正常读档、物品数量和装备耐久正确。每次修改前会创建新的备份；成功验证后，同一槽位只保留最新一份。
